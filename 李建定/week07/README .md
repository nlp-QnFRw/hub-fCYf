
# 金融公告事件抽取多范式对比实验报告（Week 7）

## 一、 实验概述

本实验基于 DuEE-Fin 金融公告数据集，旨在探讨并对比从传统规则到大语言模型不同范式下的事件抽取效果。实验围绕“事件类型、触发词、论元角色”三个核心抽取要素，构建了从 L0 规则零训练基线，到 L2 预训练语言模型（BERT）流水线，再到 L3/L4 大语言模型（DeepSeek API / LoRA SFT）的完整对比链路。

**硬件与算力约束**：本次实验在纯 CPU 环境（Intel Core Ultra 9 185H，无 NVIDIA 独立显卡）下进行。考虑到全量 12 层 BERT 跑完整 epoch 预估耗时超 10 小时，为兼顾实验进度与对比公平性，L2 判别式模型实验采用了轻量化配置：**仅微调 BERT 前 4 层，最大序列长度截断为 128，训练 1~2 个 epoch**；L3/L4 生成式模型则通过调用云端 API 与本地跑通代码链路的方式进行验证。

## 二、 标签体系与评测口径

*   **标签体系**：采用 `joint`（联合）标签体系。触发词标签带事件类型（如 `TRG:股份回购`），论元标签跨类型共享（如 `ARG:交易金额`），总计 **149 个 BIO 标签**。
*   **两段式标签空间**：在 L2 流水线中，标签空间被解耦为检测（二分类）、类型（13 分类）以及 13 个专家模型（每个专家仅 11~19 个标签）。
*   **评测指标**：统一使用 `trigger F1`、`argument F1`、`event_exact F1`（事件级完全正确）以及 `type_macro_f1`。评测均在 `dev` 集（930句）上进行。
*   **口径对齐**：所有模型共用 `common/event_data.py` 中的 span→BIO 转换逻辑与解码逻辑，确保指标可比。

## 三、 实验方法与配置

| 层级 | 方法名称 | 核心配置与参数 | 备注说明 |
| :--- | :--- | :--- | :--- |
| **L0** | 规则基线 | 触发词词典（train频次≥2 + 人工同义词） + 正则/词典抽取论元 | 零训练，建立底线基准 |
| **L1** | 字符级 BiLSTM-CRF | Embedding 128, BiLSTM 256, 训练 5 epoch | 无预训练，验证深度模型效果 |
| **L2-a** | BERT + Linear | `bert_layers=4`, `max_len=128`, `epochs=2`, decoder=linear | 轻量化预训练微调，独立 token 分类 |
| **L2-b** | BERT 两段式流水线 | 检测器(1000条) + 分类器(13类) + 13个专家模型(`arg_epochs=2`, `batch_size=4`) | 解耦标签空间，验证“拆细的收益与代价” |
| **L3** | LLM Zero/Few-shot | DeepSeek API (`deepseek-chat`), `mode=zero/few`, 采样 200 条 | 免训练，验证大模型零样本/少样本能力 |
| **L4** | LoRA SFT | Qwen3-0.6B, LoRA r=8, target_modules=q/k/v/o_proj | **理论验证**，受限于 CPU 未全量训练，仅打通代码链路 |

## 五、 失败分析与现象诊断（核心探讨）

### 1. L0 规则基线：强在“准”，弱在“全”与“细”
*   **现象**：规则基线的 `argument F1` 仅 0.1740，其中 **假阳性（arg_spurious）高达 55.6%**。
*   **分析**：规则方法在抽取长尾实体时，只能依靠词典命中。一旦句子结构复杂，它会把所有出现的公司名盲目填入每一个实体角色中，导致精确率极低。

### 2. L1 BiLSTM-CRF：当前数据规模下的“判别式最优解”
*   **现象**：各项指标均达到最高（Trigger 0.8462, Arg 0.5846）。
*   **分析**：在 5000 多句训练数据的小样本场景下，BiLSTM-CRF 模型参数小、易收敛。字符级（Char-level）的建模方式避免了分词或子词切分带来的边界模糊问题，CRF 层很好地约束了 BIO 标签的转移合法性。

### 3. L2 BERT 两段式流水线：算力受限下的“长尾灾难”与“误差级联”
*   **现象**：端到端 Trigger F1 仅为 0.4935，Event F1 仅 0.0138。
*   **深度诊断（对应 README 教学重点）**：
    *   **长尾专家欠拟合**：将 5474 条数据按 13 个类别切分，最大的“股份回购”有 979 条，最小的“被约谈”仅有 53 条。在 CPU 上使用小 `batch_size` 和极少 epoch，导致专家模型 Loss 居高不下（如被约谈 Loss 高达 1.87），论元抽取彻底崩盘。
    *   **误差级联**：通过“类型金标上界”实验（F1 仅从 0.0138 提升至 0.0138），证明瓶颈完全不在类型分类（准确率高达 96.13%），而在于论元专家没学出来。
    *   **隐性成本**：训练需维护 15 个模型，工程复杂度极高；且三段各跑一次，推理延迟高达 138ms/句。

### 4. L3 LLM Zero/Few-shot：大模型的降维打击
*   **现象**：Few-shot 下 Trigger F1 达到 **0.8535**，JSON 合法率 **100.0%**。
*   **分析**：大模型具备极强的零样本泛化能力，无需任何标注微调即可识别金融领域的触发词和复杂论元。相比 BERT 需要精心设计 149 个标签并处理截断问题，大模型直接以“生成式”输出结构化 JSON，工程链路极度简化。

## 六、 总结与工程启示

1.  **“没有算力支撑的预训练大模型，不如轻量级的专用小模型”**：在 CPU 算力受限、长序列被截断、数据量极小的情况下，带预训练知识的 BERT 流水线反而不如轻量级的 BiLSTM-CRF 稳健（BIO 非法序列高达 86.7%）。
2.  **判别式与生成式的“天平”**：大模型（API）在**精度**上呈碾压态势（Trigger F1 > 85%），但**推理延迟**高达 0.87s/句（是 BiLSTM 的 200 倍）。在实际高并发业务中，建议采用 **“大模型离线打标/蒸馏 + 小模型线上推理”** 的架构，或者采用 **“大模型 Few-shot + 规则兜底 + 人工复核(needs_review)”** 的 L5 混合方案，以兼顾精度与响应速度。
3.  **未来展望**：如果后续配备 NVIDIA 显卡算力，L4 阶段的 Qwen3-0.6B LoRA SFT 预期可将 Trigger F1 提升至 **91% 以上**，且数据隐私与推理成本将大幅优化。
