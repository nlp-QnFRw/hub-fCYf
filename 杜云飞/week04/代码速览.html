为什么 loss 密度是 100%

输入 x = ids[:-1]、标签 y = ids[1:]，这样一个长度为 512 的窗口会产生 512 个预测任务，每一个位置都在预测"下一个字是什么"。这就是课程里说的"next-token prediction 让每个 token 都参与 loss"，对比 BERT 只对被 mask 掉的 15% 算 loss，信号密度高一个量级。 注意位移是在 train.py 造数据时做的，model.py 里只做交叉熵，不重复 shift。 

# train.py 的数据集：随机取一个窗口，切一刀就得到 (x, y)
i = torch.randint(0, len(ids) - block_size - 1, (1,)).item()
x = ids[i : i + block_size]          # 前 512 个
y = ids[i + 1 : i + block_size + 1]  # 后移一位，就是每个位置的"正确答案"

Pre-Norm 与 Post-Norm

这个项目：Pre-Norm

x = x + Attn(Norm(x))
x = x + FFN(Norm(x))

归一化在子层之前。残差主路上是一条干净的恒等通路，梯度不经过 norm 的缩放， 8 层不加精细 warmup 也不容易崩。代价是最后必须补一个 norm_f，否则输出尺度不受控。

原始 GPT-2：Post-Norm

x = Norm(x + Attn(x))
x = Norm(x + FFN(x))

归一化在残差之后。每一层都往主路上插一次缩放，层数一多梯度就衰减， 必须靠 warmup 小心翼翼地起步。深层网络基本已经淘汰这个写法。

为什么输入输出形状一定相同

每个 Block 都是 (B,T,D) → (B,T,D)。这个性质是"能无脑堆 N 层"的前提—— 堆 8 层和堆 80 层，除了显存和耗时，接口完全一样。scaling.py 换 preset 时只改 n_layer / d_model / n_head 三个数，其余代码一行不动，靠的就是这个不变式。

03

RMSNorm y = x / rms(x) · g

一句话：LayerNorm 去掉"减均值"和"加偏置"之后，剩下的就是 RMSNorm。 看起来像偷工减料，但实验上几乎不损失效果，而每一层都少一次逐元素运算。

逐元素走一遍（取真实数据）

输入向量 x = [2, −1, 0.5, 3]，下面四行是同一组数在不同阶段的取值。

每一组是一个分量（x₀~x₃），组内四根柱是四个阶段的取值。 关键差别看绿色和蓝色两组： RMSNorm 只是整体缩放，四个值的正负格局原样保留；LayerNorm 强行把均值拉到 0， 分布被重新排布。灰色那根就是被减掉的均值本身。

两行代码，没有 bias

rms = x.pow(2).mean(-1, keepdim=True).add(eps).rsqrt()
return (x * rms) * self.weight
可学习参数g ∈ R³⁸⁴，初始全 1
bias没有
减均值没有
整模型 norm 参数占比0.04%（6,528 个）
eps1e-6

rsqrt() 是 1/√x 的融合算子。写成 1/torch.sqrt(...) 数学等价， 但会多一次 kernel 和一次中间张量。

容易误解的地方：RMSNorm 并不"更简单所以更弱"。它砍掉的是冗余—— 对 384 维向量来说，减均值只改变一个自由度，而计算要遍历全部 384 个元素。 Llama、Qwen、GLM 全系都是这个选择，不是这个项目的省事做法。
04

RoPE 旋转位置编码 让内积只跟相对距离有关

Self-Attention 本身是置换等变的：把输入打乱，输出跟着打乱，每个位置算出的东西一模一样。 也就是说"猫追狗"和"狗追猫"在它眼里没有区别。位置信息必须从外面注入。

① 把 (x₁,x₂) 按位置转一个角度

拖动滑块改变 token 的位置，看这对 q/k 的二维分量怎么转。频率固定时， 两个 token 的内积只取决于它们的角度差，也就是位置差。

当前角度—
与 pos=0 的内积—

② 32 个频率，各管一段距离

每头 64 维 → 配 32 个旋转频率，从 θ₀=1 一路衰减到 θ₃₁≈1/1000062/64。 高频转得快，负责分辨"隔壁字"；低频转得慢，负责分辨"隔了几段"。

横轴是相对距离 Δ，纵轴是 cos(Δ·θ)。五条线是五组不同频率： 间隔越小振荡越快。一组频率覆盖不了所有尺度，32 组叠起来才有"既知道相邻、也知道段落"的效果。

实现只有三行

# 1. 预计算：位置 × 频率，做成表（不是参数）
inv_freq = 1.0 / (base ** (arange(0, hd, 2) / hd))
freqs = outer(pos, inv_freq)        # (T, hd/2)
emb   = cat([freqs, freqs], -1)     # (T, hd)
cos_t, sin_t = emb.cos(), emb.sin()

# 2. 旋转：[−x₂, x₁]
x1, x2 = x.chunk(2, -1)
rotate_half = cat([-x2, x1], -1)

# 3. 作用到 q 和 k（v 不动）
out = x * cos_t + rotate_half(x) * sin_t
新增参数0 个
表存哪register_buffer，不算参数
为什么预计算只跟位置有关，与数据无关
v 要不要旋转不要，只有 q/k 带位置
decode 时位置怎么定= 已有缓存长度 offset
超长怎么办_refresh_rope() 动态扩展
和可学习位置编码的差别：那种要 512×384 ≈ 19.7 万参数，而且训练时只见过 ≤512 的位置， 喂进 600 就完全没见过。RoPE 是算出来的，理论上可以外推（实际会衰减，但比查表好得多）。
为什么"旋转"能编码相对位置：二维旋转矩阵乘上去，两个向量各自转了 p₁θ 和 p₂θ， 它们的内积里只剩下 cos((p₁−p₂)θ) 这一项——绝对位置 p₁、p₂ 都消失了，只有差留了下来。 这就是"天然相对"的代数来源，不是工程 trick。
05

Causal Mask 第 i 行 = 第 i 个 token 能看谁

鼠标划过任意一行，看这个位置的 token 能看见哪些位置。训练时这张矩阵是固定的下三角， 和输入内容无关——这是"自回归"三个字的全部含义。

蓝色 = 可见，暗色 = 被屏蔽。对角线永远是蓝色：每个 token 至少能看见自己。

悬停某一行查看

8×8 只是示意，真实训练时是 512×512。 

scores = q @ k.transpose(-2,-1) / sqrt(hd)
mask   = (cols <= rows)              # True=可见
scores = scores.masked_fill(~mask, -inf)
w      = softmax(scores, -1)         # -inf → 权重 0
y      = w @ v
为什么是 −inf 不是 0：softmax 里 exp(0)=1，填 0 等于给了一个"中性偏好"， 被屏蔽的位置仍会分走一份权重。exp(−inf)=0 才是真正的"看不见"。
代码里有两套实现：fast_attn=True 走 PyTorch 融合核（默认，快）； False 走手写的 masked_fill（慢，但能把 mask 打印出来讲原理）。 两套在同一个 forward 里用 if 分开，教学和实用兼得。

decode 时 mask 为什么会算错

训练时 q 和 k 一样长，用 is_causal=True 就够了。但生成第 100 个 token 时， q 只有 1 行、k 有 101 行，PyTorch 的 is_causal 默认按"右上角对齐"来切， 会把这一行错判成全可见。所以代码里显式算了一个 (T, Tk) 的布尔矩阵： 

rows = arange(T).view(-1,1) + (Tk - T)   # query 的绝对位置
cols = arange(Tk).view(1,-1)             # key 的绝对位置
attn_mask = (cols <= rows)               # 只允许看"不晚于自己"的

这是工程上最容易踩的一个坑：小模型测试时 q/k 等长，一切正常；接了 KV Cache 之后才开始胡说， 而且报错不报在 attention 里，报在生成结果上。

06

KV Cache 生成第 t 个字要重算多少

自回归生成最朴素的做法是：每生成一个字，就把"提示词 + 已生成的全部"重新喂一遍。 前面的 K/V 每次都被重算，而这些值其实一个都没变。

不用缓存

每步都跑完整序列。第 t 步要处理 t 个 token，累计 O(T²)。 T=512 时累计约 13 万次 token 前向。

有缓存

每步只算 1 个新 token，历史 K/V 直接读。累计 O(T)。 代价是显存：每层存 2×T×384 个 bf16。

三个必须一起改的地方

① RoPE 的 offset

新 token 的绝对位置不是 0，而是已有缓存长度。所以 cos[offset:offset+T] 切片， 否则每个字都以为自己是第一个字。

② mask 的形状

q 有 1 行、k 有 Tk 行，得手算 (T,Tk) 的可见矩阵， 不能直接用 is_causal=True。

③ cache 的传递

每个 Block 返回自己的 (k,v)，主循环收集成 list，长度 = n_layer。 下次前向时按层号对应喂回去。

实测差距

无缓存
基准
有缓存
≈6~8× 快

sample.py 里的 bench_kv() 会现场跑一遍并打印真实倍率。序列越长差距越大， 因为省掉的是二次项。短 prompt（十几个字）时差距不明显，这也是很多人误以为"缓存没用"的原因。

07

SwiGLU 与参数账 16,141,056 花在哪

FFN 占了接近六成参数，是所有小模型里最"吃预算"的部分。SwiGLU 的做法是多开一条门控支路， 然后把中间维压到 4D 的 2/3，让总参数量和经典 FFN 持平。

门控结构

hidden = int(D * 4 * 2/3)   # 384 → 1024
hidden = (hidden + 63) // 64 * 64  # 对齐 64
out = w2( silu(w1(x)) * w3(x) )

为什么是 2/3：SwiGLU 有三块矩阵（w1/w2/w3），经典 FFN 只有两块。多出来的那一块， 正好要靠"中间维缩到 2/3"来抵消，两者参数量才等价。

Embedding（与 lm_head 共享）1,978,75212.3%

weight tying 省下的钱

lm_head 如果独立，要多 5153×384 = 1,978,752 参数， 模型从 16.14M 涨到 18.12M，+12.3%。

共享的理由不只是省钱：输入层做"字符 → 向量"，输出层做"向量 → 字符"， 本来就是同一张查找表的两面。共享之后两边梯度一起更新，表征也更一致。 代价是"输入嵌入"和"输出映射"被迫用同一个尺度，表达能力略有损失——在 16M 这个量级，这笔交易划算。

独立 lm_head18,119,808
实际（共享）16,141,056
省掉1,978,752（12.3%）
实现lm_head.weight = embed.weight
注意必须放在 init 之后赋值
顺序陷阱：self.apply(self._init) 会把 lm_head 也重新初始化一遍。 如果先 tie 再 init，共享的那块 tensor 会被覆盖两次（虽然结果差不多，但语义上不对）。 所以代码里是 先 init，最后一句才赋值共享。

09

sample.py 采样策略 logits → 一个字，中间发生了什么

模型只吐 logits，怎么把它变成"一个字"是另一套东西。这里的顺序很关键： 温度 → 封禁 → 重复惩罚 → top-k → softmax → top-p。顺序错了结果会不一样。 下面可以拖动滑块，实时看分布怎么被裁。

一维分布被逐层裁剪

柱子高度 = 归一化后的概率。变暗的柱子 = 被某一层策略砍掉（概率归零）。 横轴是 12 个候选 token。

温度的作用缩放 logits
K 的作用硬截断
P 的作用累积概率截断

Top-P 的一个细节：边界怎么取

课程里写的是 cum <= P，代码里写的是 prev < P（prev = 不含自己的累积）。 两者只差"会不会多留一个 token"，但后者有两个好处：排名第 1 的 token 的 prev 恒为 0， 所以永远保留，P 调到 0.01 也不会出现"全军覆没"；以及不会出现"刚好达到 P 又多带一个"的边界抖动。

六种策略在 sample.py 里都能跑

greedyargmax，确定性最强，容易复读
temperature只用温度，看分布形状变化
top-k硬截断到 K 个
top-p核采样，候选数随分布自适应
beam search保留 beam 条路径，找最大似然
repeat penalty压低已出现的 token（先去重）

为什么重复惩罚要先去重

如果一个字已经出现 10 次，逐次惩罚会让它的分数被压低 10 遍， 直接压到 −inf 附近，模型再也不敢用这个字。代码里 sorted(set(prev_ids)) 先转成集合，一个 token 只惩罚一次。

另一半细节：正分数除以 rp，负分数乘以 rp。两个方向都是"更不可能"， 但保持单调性，不会把排序搞乱。

为什么不用 FastAPI

单用户、几个路由，装框架不划算。标准库意味着"复制到别的电脑也能跑"。

"对话"是假的

模型只学过续写，没有指令微调。多轮历史被拼成一段文本喂回去，它是在"接着写"而不是"回答"。

为什么要 ban_ids

聊天界面里压掉 EOS，否则模型十几个字就收尾。这是"界面需求"倒逼采样参数。

scaling.py：同一个 token 预算，只改模型大小

五档 + 一个 LSTM 对照组，token 预算相同。注意 LSTM 那条：参数量 15.96M，和 base 的 16.14M 几乎一样， 但 val loss 4.249 明显更差。同等参数下 Transformer 更强，这就是换掉 LSTM 的直接证据。 另外 base 档 val 反而比 small 差一点，是因为 1.8 分钟太短、没训透——这也说明小模型在小预算下"更划算"。

一页速查 所有"为什么"压缩成卡片

回头查代码时，先在这里定位是哪一类问题。

norm
为什么 RMSNorm 不减均值

减均值只改变一个自由度，却要遍历全部 384 个元素。后面紧跟线性层，偏移本来就能被吸收。

rope
为什么位置编码要"旋转"

旋转后两个向量的内积只剩 cos((p₁−p₂)θ)，绝对位置消失、相对距离留下。零参数，且天然外推。

attn
为什么 mask 填 −inf 而不是 0

softmax 里 exp(0)=1 会分走权重，exp(−inf)=0 才是完全不可见。

attn
为什么要除以 √hd

q·k 是 64 个数相乘求和，维度越高数值越大，softmax 会饱和成 one-hot。除以 √64 把方差拉回 1。

ffn
为什么 SwiGLU 是 2/3

三块矩阵 vs 经典两块，中间维缩到 4D×2/3 才能让总参数量等价。

ffn
为什么 hidden 取 64 的倍数

对齐显存块，tensor core 更喜欢这种尺寸。1024 刚好已经是 64 的倍数。

init
为什么残差层要缩小初始化

proj 和 w2 在残差主路上，输出会被 8 层反复累加。标准差按 1/√(2N) 缩，否则激活指数级放大。

init
为什么 tie 要放在 init 之后

apply(_init) 会重新初始化 lm_head。先 tie 再 init 等于把共享张量覆盖两次。

train
为什么必须 warmup

AdamW 动量初值是空的，前几步有效步长异常大。6e-4 直接砸下去，几十步内就 NaN。

train
为什么 loss 在 fp32 算

bf16 只有 8 位尾数，交叉熵里 log(sum(exp)) 的精度不够，会让梯度噪声变大。

infer
为什么 KV Cache 要改 mask

q 长 1、k 长 Tk，is_causal 按右上对齐会判成全可见，必须手算 (T,Tk) 的布尔矩阵。

infer
为什么 decode 时位置是 offset

新 token 的绝对位置 = 已有缓存长度。用 0 会让每个字都以为自己是第一个字，上下文全乱。

sample
为什么重复惩罚要去重

同一个字出现 10 次会被惩罚 10 遍，直接压到 −inf。先 set() 再惩罚。

sample
为什么 top-p 用 prev < P

排名第 1 的 prev 恒为 0，永远保留，P 再小也不会全军覆没；也不会边界多留一个。

data
为什么 val 比 train 还低

不是 bug。数据量远大于模型容量，属于欠训练；train loss 是训练中滑动的，天然偏高。

data
为什么 16M 会胡说事实

容量限制，不是训练问题。它学的是"中文怎么连成句子"，不是"世界知识库"。
