# 实验计划与预算（docs/PLAN.md）

> 记录"打算怎么跑"与"实际怎么跑偏了"。偏差是正常的，不记录才是问题——
> 下次复盘时，唯一能解释"为什么某个 run 没做"的就是这张表。

## 1. 变量清单与单变量原则

每次只改一个变量，其余全部锁死。锁死的默认值：

| 项 | 值 | 依据 |
|---|---|---|
| seed | 42 + `cudnn.deterministic` | 无 seed 时同命令两次 val_acc 差 0.51pp |
| batch_size（BERT） | 32 | 实测 121 samples/s @4.3GB；bs=64 只有 36 |
| 主干学习率 | 2e-5 | BERT 微调惯例；消融 ±1 档 |
| 头部学习率倍数 | 3.0 | 头随机初始化，学得更快 |
| warmup_ratio | 6% | 线性 warmup + 线性衰减 |
| dropout | 0.1 | 消融对照 0.3 |
| max_len | 256 | 覆盖率与吞吐的折中（见 figures/len_dist.png） |
| 截断策略 | head_tail（标题 + 前 60% + 后 40%） | 新闻导语与结语都带类别线索 |
| 早停 | 按 val macro-F1，最多 epochs 轮 | epoch 数本身就是消融项 |
| 训练集 | train_100k（分层，按自然分布） | 全量 74 万跑不动消融 |
| 主指标 | test_bal 上 macro-F1 | 每类 ≥300，长尾 F1 才可信 |

## 2. 三层预算（实测吞吐推算，不是拍脑袋）

| 层 | 内容 | 数量 | 预计 |
|---|---|---|---|
| Tier-1 | 规则 + TF-IDF×3 + BERT 基线(100k) + 3 主干对比(30k) + 本地 LLM 4 档 shot + LoRA 基线 | 13 | ≈ 3.4 h |
| Tier-2 | 长度 4 格、截断 2 格、池化/冻结 2 格、优化 6 格（30k×2ep，10~12 min/格） | 13 | ≈ 3.2 h |
| Tier-3 | Qwen3 对比、LoRA rank/数据量/target 消融、100k 学习率确认 | 8 | ≈ 3.1 h |
| 合计 | | **34 个 run** | **≈ 9.7 h** |
| 预留 | 冒烟、失败重跑、调试 | — | ≈ 2 h |
| **总计** | | | **≈ 12 h**（预算 10~15h） |

实测锚点（`docs/PROBE.md`）：BERT 100k×1ep@L256 = 14 min；LoRA 10k×3ep@L384 = 42 min；
本地 LLM 生成 40 条/s（1000 条约 25s）。

## 3. "30k 调参 + 100k 确认"的适用边界

| 能用 | 不能用 |
|---|---|
| max_len、lr、池化、冻结层、损失加权、截断策略（结构性超参，排序在 30k 与 100k 上稳定） | 数据量曲线（变量本身就是规模）、主干对比（必须固定规模）、LoRA rank（小数据上差异会被噪声淹没） |

**已知偏差**：100k 的 1 epoch 更新次数是 30k 的 3.3 倍，等效学习率更高，
所以 30k 上调出的最优 lr 在 100k 上通常要**下调一档**——Tier-3 里的
`bert-base-l256-100k-3ep-lr1e5` 就是为验证这一条而设的。

## 4. 砍单顺序（超预算时按序砍，永不砍的写在最后）

1. `dropout 0.3`（结论大概率"不敏感"）
2. `warmup 0`（同上）
3. `batch_size 16`
4. `lora targets=qv`
5. `qwen3 2shot`
6. `lora 20k`（最贵的 Tier-3）

**永不砍**：数据量曲线、max_len 消融、class_weight 消融、LoRA 基线、规则与 TF-IDF 下限。

## 5. 执行记录（跑完后回填）

| 时间 | 事件 |
|---|---|
| D0 | 环境探针通过：tokenizer 可离线加载、BERT bs32/L256 = 121 samples/s / 4.32GB、LoRA bs2/L384 = 12.1 samples/s |
| D0 | 发现 `expandable_segments` 在 Windows 不支持 → 改为按平台设置 |
| D0 | 实测 `.half()` + GradScaler 报 `unscale FP16` → 全线改 bf16 无 scaler（性能几乎不变） |
| D0 | THUCNews.zip 直链可用但速率波动大（40KB/s ~ 700KB/s），改用 `curl -C -` 断点续传 |
| D0 | zip 内文件名是 **UTF-8 但无 0x800 标志**，按 GBK 还原会错得更多；另发现 83 万个 `__MACOSX` 垃圾成员 |
| D0 | 解析完成：**834,958 篇**（官方称 74 万，实际 83.5 万），耗时 55 秒；标题命中率 98.3%；精确去重剔除 1,116 条 |
| D0 | 真实分布与预期不同：**科技 162,818 是头部**（不是财经），星座 3,576 是尾部，**长尾比 45.5×**（远超 10× 预警线） |
| D0 | 长度统计：max_len=256 仅完整覆盖 **15.6%** 样本，平均丢弃 71.6% 的 token —— 长文本消融会很关键 |
| D0 | **tokenize 缓存没带数据指纹** → "100k×3ep" 实际只训了 1200 条合成样本（val 卡 0.44）。缓存键补上 `文件大小+mtime` 并校验条数后重跑 |
| D0 | `metrics.py` 的主题层口径错误：`教育` 既是细分类又是组名，组名映射成 -1 后 acc 虚高成 1.0 → 增加 `labels=` 参数传 `GROUPS` |
| D1 | 已跑完 7 个 run：规则 2min / TF-IDF×3 5~7min / BERT 100k×3ep **51.5min** / Qwen 零样本 7.4min / LoRA 10k×3ep **56.5min** |
| D1 | BERT 单 epoch 实测 1030s（17.2 min），比探针的 14 min 慢 23%——真实数据 padding + 热降频（77~79°C，功耗 84W→72W） |
