## 1. 数据

| 项 | 值 |
|---|---|
| 来源 | THUCTC 官方 `THUCNews.zip`（1,560,309,796 字节，HTTP Range 校验） |
| 实际篇数 | **834,958**（官方宣称 74 万；zip 内另有 83 万个 `__MACOSX` 垃圾成员，已剔除） |
| 类别 | 14 类；头部**科技 162,818**，尾部**星座 3,576**，**长尾比 45.5×** |
| 文本长度 | 平均 **937 字**；标题均值 18.9 字，98.3% 的样本能拆出标题 |
| 去重 | 正文 md5 精确去重，剔除 1,116 条（0.13%） |

**切分**（seed=42，互不重叠）：

| 集合 | 规模 | 用途 |
|---|---|---|
| `train_100k` | 99,993 | 主训练集（按自然分布） |
| `sub_1k/5k/10k/20k/30k/50k` | 嵌套子集 | 数据量曲线、超参消融 |
| `val_10k` | 9,993 | 早停 / 选超参 |
| `test_nat_10k` | 9,993 | acc（贴近线上分布） |
| `test_bal` | 4,200 | **macro-F1 主指标**（每类 300 条） |

**为什么两个测试集**：按比例抽 10k 时"星座"只有 42 条，其 F1 的 95%CI 半宽超过 ±10pp，
任何"这个类提升了"的结论都不可信；而按比例算 acc 才贴近真实部署。
所以主指标在 `test_bal` 上算、辅助指标在 `test_nat_10k` 上算，两者分开汇报。

### 1.1 长度：本项目最容易被忽略的事实

| max_len | 完整保留的样本 | 平均丢弃 |
|---|---|---|
| 128 | 5.4% | 721 token（85.1%） |
| **256** | **15.6%** | **606 token（71.6%）** |
| 384 | 27.6% | 506 token（59.8%） |
| 512 | 39.2% | 421 token（49.7%） |

新闻正文平均 937 字，中文几乎 1 字 = 1 token。**任何"截断到 256 就够"的说法都需要被这张表检验。**
因此输入构造统一采用 `head_tail`（标题 + 前 60% + 后 40%），而不是纯 head。

## 2. 实验口径（对比能成立的前提）

- **同一批样本**：所有方法在 `test_bal` 与 `test_nat_10k` 上评测，样本 id 来自 `all.jsonl` 的全局行号。
- **同一个指标函数**：`common/metrics.py`，生成式的拒答/解析失败**计入分母**（算错），失败率单列。
- **同一个截断实现**：`common/text.py`，三条方法线共用（否则 max_len 消融比的是两种输入构造）。
- **固定 seed=42**，`cudnn.deterministic=True`。
- **配对检验**：`eval/paired_test.py`（McNemar 精确二项检验），不拿小数点当结论。

**配对检验（McNemar，同一批 4200 条，`test_bal`）**：

| 对比 | 差值 | p 值 | 结论 |
|---|---|---|---|
| BERT vs TF-IDF-SVM | +3.98pp | <0.0001 | 高度显著，微调确实有效 |
| TF-IDF-SVM vs LoRA | +11.45pp | <0.0001 | 高度显著，**5 分钟 CPU 打败 57 分钟 GPU** |
| LoRA vs Qwen zero-shot | +28.12pp | <0.0001 | 高度显著，SFT 修好了"标签空间不闭合" |
| Qwen zero-shot vs 关键词规则 | +0.64pp | **0.514** | **不可分辨**：0.5B 零样本 ≡ 关键词，但贵两个数量级 |
| TF-IDF LR vs SVM | −0.71pp | 0.0002 | 显著，SVM 更好（但没概率） |

**读法**：`macro-F1` 看各类是否均衡，`acc` 看真实分布下的整体正确率，两者差得越多说明模型越偏向头部大类。

## 3.1 主干对比：换主干值不值 1.4pp

同一批数据（`sub_30k` × 2 epoch）、同一套超参，只换预训练权重：

| 主干 | macro-F1 | acc | 主题F1 |
|---|---|---|---|
| bert-base-chinese | 0.8588 | **0.8896** | 0.9010 |
| chinese-roberta-wwm-ext | **0.8736** | 0.8820 | 0.9086 |
| chinese-macbert-base | 0.8729 | 0.8783 | **0.9137** |

**roberta 与 macbert 打成平手（差 0.07pp），都比 bert-base 高约 1.4pp macro-F1；但三者的自然分布 acc 恰好反向排列。** 这不是噪声能解释的方向性差异，而是同一个取舍的两面：

- 更强的预训练让模型在**长尾类**上更有把握（星座、彩票、时尚），macro-F1 因此上升；
- 但它也更容易把"边界样本"判给语义相近的大类，`acc` 在头部占主导的自然分布上反而略降。

**结论**：主指标是 macro-F1（每个类都不能掉队）时，换 roberta 值得，代价几乎为零（权重同量级、训练时间几乎不变）；只看整体准确率则 bert-base 够用。

## 3.2 数据量曲线：瓶颈在数据，不在模型

同一配置（`bert-base`、`max_len=256`、3 epoch），只改训练集规模（子集严格嵌套）：

| n_train | 5k | 20k | 50k | 100k |
|---|---|---|---|---|
| macro-F1 | 0.7898 | 0.8572 | 0.9075 | **0.9628** |
| 相对上一档 | — | +6.7pp | +5.0pp | +5.5pp |

**每翻一倍多一点就涨 5~7pp，到 100k 仍未见拐点。** 这条曲线比任何单点指标都更有决策价值：

- 数据是这个任务当前的**主约束**。把 8GB 显卡的算力全花在调参上，不如把训练集从 30k 扩到 100k（+10.4pp）；
- 反过来说，`sub_30k` 上那些 ±1pp 的消融差异，本质是在"欠拟合区"里比较细节——**先加数据，再调参**；
- 也部分解释了为什么 LoRA（只训 10k）打不过 TF-IDF：不是生成式路线不行，是它只看到 1/10 的数据。

## 4. 逐层解读

### L0 规则 / 关键词（macro-F1 0.539）

14 类 × 10~15 个强关键词，标题权重 ×2。它证明了两件事：
1. 新闻类别的**头部信号非常强**（"涨停"→股票、"中超"→体育），一半样本靠词表就能分对；
2. 但它也是**校准最差**的方法：ECE 0.239，意味着"高置信错误"大量存在——
   这正是后续做置信度闸门时必须用模型概率、而不是规则命中的原因。

### L1 TF-IDF（macro-F1 0.914~0.924）

| 配置 | macro-F1 | acc | 拟合耗时 | ECE |
|---|---|---|---|---|
| char_wb(1,3) + LinearSVC | **0.9237** | **0.9491** | 63s | N/A（无概率） |
| char_wb(1,3) + LR | 0.9166 | 0.9459 | 171s | 0.018 |
| jieba 分词 + LR | 0.9144 | 0.9419 | 103s | 0.022 |

三个结论：
- **字 n-gram 优于分词**（+0.2~0.9pp）。中文新闻里的实体（"双色球""沪指"）在分词器眼里会被切碎，
  字 1-3 gram 反而更稳，且不需要额外依赖；
- LinearSVC 比 LR 高 0.7pp 且快 2.7 倍，**代价是没有概率**——所以它不能用于置信度路由；
- TF-IDF 的 ECE 只有 0.018，比 BERT 的 0.027 还低。**"深度模型概率更准"是错觉**，
  LR 在高维稀疏特征上天然校准得好。

### L2 BERT 微调（macro-F1 0.9628）
| 指标 | 值 |
|---|---|
| val macro-F1 | 0.9659（ep3，仍在缓升，未见明显过拟合） |
| test_bal macro-F1 | **0.9628** |
| test_nat acc | **0.9701** |
| 主题层 F1（14→6 组） | 0.9767 |
| ECE | 0.0268 |
| 单 epoch | 1030s（17.2 min，含 10k val 评估） |
| 显存峰值 | 4.53 GB |
| 推理 | 2.7 ms/条（bs=32 摊薄后） |

相对 TF-IDF 的 **+3.9pp**（0.9237→0.9628）是这次实验里最大的一次跃升，
但它花掉了 55 分钟 GPU 时间，而 TF-IDF 只要 5 分钟 CPU。**这个交换是否值得，取决于你要那 4 个点做什么。**

- 训练曲线 `train_loss 0.248 → 0.086 → 0.043`，`val_loss 0.126 → 0.130 → 0.136`：
  第 2 个 epoch 起 val_loss 已开始回升，**最优轮数其实是 2~3，再加 epoch 只会过拟合**；
- 最差类别是**科技**（F1 0.923，精确率仅 0.889）：它把大量"财经/游戏"新闻吸过来，
  因为科技新闻里也大量出现"公司/发布/产品"这类词；
- 主要混淆对：财经→股票 14 条、彩票→体育 10 条、游戏→科技 9 条。
  **财经/股票的混淆是标注体系本身的问题**（宏观财经与个股行情边界模糊），不是模型能力问题。

### L3 本地小模型 zero-shot（Qwen2-0.5B-Instruct）

| 指标 | 值 |
|---|---|
| macro-F1（`test_bal`） | **0.5437** |
| acc（`test_bal`，全样本计入分母） | 0.5271 |
| acc（`test_nat_10k`） | 0.5274 |
| **拒答率** | **20.4%**（`test_bal` 855/4200） |
| 若只算解析成功 | acc 0.662 → **虚高 13.5pp** |

两个必须讲清楚的现象：

1. **它和关键词规则打平（0.539 vs 0.544），但成本高出两个数量级。**
   0.5B 模型的通用语义能力无法弥补"没在这个标签体系上训练过"这件事。

2. **拒答不是格式问题，是"标签空间不闭合"问题。** 抽检 855 条拒答：
   模型输出的是 `足球`（而不是 `体育`）、`NBA`、`美股` 这类**语义正确但不在 14 类白名单里**的词。
   集中在时政（184）、星座（137）、房产（119）——恰好是标题里大量出现专有名词/口语表达的类。
   这解释了为什么"只算解析成功"的 acc 会虚高 13.5pp：**被丢掉的样本并不是随机丢的，而是难度更高的那一批。**

> 这也是 L4（LoRA）存在的理由：不是"让模型更聪明"，而是**让它学会只输出这 14 个词**。

### L4 LoRA SFT（Qwen2-0.5B，10k×3ep，可训练 1.08M / 0.218%）

| 指标 | 值 |
|---|---|
| macro-F1（`test_bal`） | **0.8104** |
| acc（`test_bal`） | 0.8083 |
| acc（`test_nat_10k`） | 0.8578 |
| **拒答率** | **0.6%**（zero-shot 是 20.4%） |
| 训练曲线 | train 0.139 → 0.049 → 0.025；**val 0.077 → 0.051 → 0.064** |
| 单 epoch | 994s / 1174s / 1223s（逐轮变慢，见下） |
| 显存峰值 | 4.60 GB |

三个结论：

1. **SFT 的主要收益不是"更聪明"，而是"学会闭嘴"。** 拒答率 20.4% → 0.6%，
   准确率 0.527 → 0.808（+28.1pp，p<0.0001）。零样本那 855 条拒答里大量是
   `足球`/`NBA`/`美股` 这种"语义对、不在白名单"的输出，微调后模型被强制收敛到 14 个词上。
2. **第 3 个 epoch 开始过拟合。** val_loss 0.051 → 0.064 回升，而 train_loss 还在降
   （0.049 → 0.025）。**最优轮数是 2**，多训的那一轮是在记噪声。
3. **它仍然输给 TF-IDF 11.5pp、输给 BERT 15.2pp。** 0.5B 的容量 + 只训 10k 条，
   在"封闭标签 + 长文本"的任务上不具备竞争力。它的真正价值是**验证了生成式路线可行**，
   以及在"必须输出结构化结果"的场景下作为可控 pipeline 的一环。

> 工程细节：三个 epoch 的耗时是 994s → 1174s → 1223s，逐轮变慢 23%。
> 这不是数据问题，是**笔记本持续满载后的热降频**（GPU 温度稳定在 77~79°C，
> 功耗从 84W 掉到 72W）。做长训练排期时要把这个 20% 的衰减算进去。

### L3' 云端 API（DeepSeek-V4.1-Flash zero-shot）：最省事的那条路

| 指标 | 值 |
|---|---|
| macro-F1（`test_bal`） | **0.8199** |
| acc（`test_nat_10k`） | 0.8038 |
| 主题层 F1 | 0.8949 |
| **拒答率** | **0.0%**（4200 + 9993 条全部解析成功） |
| 成本 | **3.02 元** / 14,193 条 |
| 耗时 | 15.2 min（并发 12） |

**这是本轮"性价比"最高的一条路线**：不训练、不改代码、3 块钱、15 分钟，就能拿到 0.8199。
它比本地 0.5B 零样本（0.5437）高 **27.6pp**，比 LoRA（0.8104）高 0.95pp——但**这个 0.95pp
在 4200 条样本上统计不可分辨（McNemar p=0.154）**。正确的说法是：

> 花 3 元和 15 分钟，就能拿到与"56 分钟 GPU 微调 LoRA"**同等水平**的结果；代价是数据出境、
> 按量计费、且无法本地部署。

对比本地 0.5B 零样本的 20.4% 拒答率，云端模型的拒答率是 **0**——它天然知道"只能从这 14 个
新闻类目里选"，不需要 SFT 去教。**"标签空间闭合"对小模型是难题，对大模型是常识。**

> 口径提醒：这是**闭源付费 API**，而它的 0.82 仍显著低于 BERT 的 0.9628
> （−14.4pp，McNemar p<1e-4）。所以它适合"没有标注数据、没有 GPU、要快速拿到可用基线"
> 的场景，不适合替代已经能训的判别式模型。

### L3'' few-shot：给例子反而更差，而且是格式问题

同样是 Qwen2-0.5B，只改示例数量（`turn` 式：每个示例一轮 user/assistant）：

| shots | macro-F1 | acc | 拒答率 |
|---|---|---|---|
| 0 | **0.5437** | 0.5274 | 20.4% |
| 1 | 0.5093 | **0.5811** | 16.0% |
| 3 | 0.3602 | 0.3290 | 48.1% |
| 5 | 0.0650 | 0.0244 | **91.6%** |

**单调恶化，5-shot 时 91.6% 的样本输出的是正文续写而不是类名**（抽检原始输出：
`'喝喝茶，看看电视，就是生活'`、`'却遭遇了职业生涯以来最差的一'`）。

这条曲线不能直接读成"few-shot 没用"——它更像是**多轮结构对 0.5B 模型不友好**：
每个示例都重复一遍 14 类清单 + 指令，模型把这段结构当成了"待续写的文本"。
所以额外做了一组 `inline` 对照（示例压进同一条 user 消息、用 `新闻：… / 类别：…` 排版），
结果见 `runs/summary.md` 的 `qwen2-3shot-inline`。

> 唯一可用的 few-shot 结论：**1-shot 让自然分布 acc 涨了 5.4pp（0.5274→0.5811）却压低了
> 长尾（macro-F1 −3.4pp）**——给了示例后，模型更敢答大类，但仍不会答小类。

## 5.5 消融：每个旋钮到底值多少分

锚点：`bert-base` / `sub_30k` / 2 epoch / `max_len=256` / lr 2e-5 / cls 池化，
macro-F1 **0.8588**。下表只改一个变量（`l512` 那行因显存同时降了 batch，见备注）。

| 改动（相对锚点） | macro-F1 | ΔF1 | acc |
|---|---|---|---|
| lr 2e-5 → **3e-5** | 0.8693 | **+1.05** | 0.8812 |
| class_weight none → **balanced** | 0.8690 | **+1.02** | 0.8738 |
| max_len 256 → **128** | 0.8674 | +0.86 | 0.8742 |
| lr 2e-5 → 1e-5 | 0.8642 | +0.54 | 0.8842 |
| freeze_layers 0 → **6** | 0.8624 | +0.37 | 0.8765 |
| dropout 0.1 → 0.3 | 0.8609 | +0.21 | 0.8858 |
| max_len 256 → 512（同时 bs 32→16） | 0.8592 | +0.04 | 0.8757 |
| pool cls → mean | 0.8565 | −0.23 | 0.8740 |
| truncation head_tail → head | 0.8541 | −0.46 | 0.8812 |
| warmup 0.06 → 0 | 0.8520 | −0.68 | 0.8835 |
| max_len 256 → 384 | 0.8519 | −0.69 | 0.8775 |
| truncation head_tail → **title_only** | 0.8118 | **−4.69** | 0.8169 |

### 用 seed 噪声做标尺，结论会变得很不一样

同配置换 `seed=42/123/2024` 三次，macro-F1 分别是 0.8588 / 0.8645 / 0.8560：

> **标准差 σ = 0.68pp，2σ = 1.36pp。** 也就是说，|Δ| < 1.36pp 的格子**只是换了个种子**。

按这个标尺重读上表：

| 类别 | 项目 | 判断 |
|---|---|---|
| **真效应** | 主干 → roberta（+1.48）、→ macbert（+1.41） | 略高于 2σ，且 McNemar p=0.0001，可信 |
| **真效应** | 截断 → title_only（−4.69） | 远超噪声，决定性因素 |
| **全是噪声** | lr 3e-5（+1.05）、class_weight（+1.02）、max_len 128（+0.86）、lr 1e-5（+0.54）、bs16（+0.42）、freeze6（+0.37）、dropout0.3（+0.21）、l512（+0.04）、pool mean（−0.23）、head（−0.47）、warmup0（−0.68）、l384（−0.69） | **12 项全部 |Δ| < 1.36pp，不能当结论** |

**这是本报告最重要的一条方法论结论：单次运行的消融，大部分"提升"是在读噪声。**
如果不做 seed 重复，我会兴高采烈地报告"lr=3e-5 涨了 1.05pp、class_weight 涨了 1.02pp"，
而实际上把种子换一下就没了。规范里那句"没有 seed 方差就不能比小数点"不是形式主义。

### 但噪声之内仍有三条可信的定性结论

**1. 只有"标题 vs 正文"是决定性的（−4.69pp，约 7 倍于 2σ）。**
去掉正文只留标题，macro-F1 掉 4.7pp、acc 掉 7.3pp——说明正文携带了标题无法替代的信息。
而 `head`（只读开头）与 `head_tail`（开头 60% + 结尾 40%）只差 0.47pp（噪声内）：
**读完整篇文章几乎没有额外收益，读开头就够了。**

**2. 长度与效果没有单调关系，且方向与直觉相反。**
128（+0.86）、256（锚点）、384（−0.69）、512（+0.04）四个点散布在 1.55pp 内且不单调。
结合 §1.1（256 只完整覆盖 15.6% 样本）可推出：**被截掉的尾部内容对分类贡献很小**，
加长反而让序列变长、每步有效样本变少。所以 `max_len=256` 是对的——不是因为够长，
而是因为**没必要更长**。

**3. 两个"提分"项的方向一致：都在拿 acc 换 macro-F1。**
- `class_weight=balanced`：macro-F1 +1.02pp / acc −1.58pp。逐类看，
  彩票 0.892→0.920、时尚 0.754→0.801、家居 0.905→0.919——**长尾类确实被救回来了**，
  机理成立，只是幅度在噪声内。
- `lr=3e-5`：+1.05pp / acc −0.84pp，同为"更激进地照顾难类"的方向。
- `freeze_layers=6`：macro-F1 +0.37pp（噪声内），但**训练时间从 10.3 min 降到 6.4 min（−38%）**。
  这是唯一一个"白拿"的优化：分数不掉、时间省四成，8GB 卡上尤其值得开。

> **seed 噪声全文基准**：三次重复的 σ = 0.68pp、2σ = 1.36pp，详见上一小节与
> `runs/summary.md`（`compare.py` 会自动计算并标注）。

## 6. 工程结论（比指标更值得带走）

1. **显存过 7GB 不是 OOM，是静默降级。** bs=64/L=256 峰值 7.24GB，吞吐从 121 掉到 36 samples/s；
   LoRA bs=8 峰值 8.75GB 甚至"成功"了（溢到 WDDM 共享内存）。所有训练脚本都带
   `max_memory_allocated < 6.5GB` 断言，越线直接报错。
2. **`.half()` + GradScaler 是错的**（`unscale FP16 gradients`）。正确做法是权重 fp32 + autocast，
   或者直接 bf16（实测 117 vs 121 samples/s，几乎无损且不用 scaler）。
3. **tokenize 缓存必须带数据指纹。** 缓存键只写 split 名时，重新生成切分后会静默命中旧缓存——
   我第一次的"100k 训练"实际只训了 1200 条，val 卡在 0.44。
4. **74 万 txt 不要解压。** 直接流式读 zip 转单 jsonl，55 秒完成；解压要写 1.8GB 且 NTFS 遍历极慢。
5. **DeepSeek-V4.1-Flash 默认是推理模型**，不显式 `thinking: disabled` 时 `max_tokens=8` 拿不到答案。

## 7. 局限与下一步

**本轮实际跑完的**：规则 1 + TF-IDF 3 + BERT 微调 5（主基线、数据量曲线 3、30k 基准 1）
+ 主干对比 2 + BERT 消融 15（含 3 个 seed 重复）+ 本地 LLM 4（0/1/3/5-shot）+ DeepSeek API 1 + LoRA 1，
合计 **32 个 run**，全部在 `test_bal` 4200 条上同口径可比。

**还没跑完的**（队列可断点续跑，`--list` 看预算）：

- **Tier-3**：Qwen3-0.6B 对比、few-shot 的 `inline` 格式对照、LoRA 的 rank / 数据量 /
  target_modules 三组消融、100k 上 `lr=1e-5` 的确认实验。这些在 23:00 提交时仍在队列里。
- **DeepSeek 3-shot**：账户余额已耗尽（0-shot 花了 3.02 元），3-shot 需要充值约 8~10 元才能跑。
  队列里已注释掉该条并写明命令。

**已知的口径局限**（比数字更重要）：

1. **seed 方差**：主表只有单次运行；Tier-2 的消融补了 3 个种子的重复，用来估噪声底。
   所有 <1pp 的差异都应以 `runs/summary.md` 里标注的 2σ 阈值为准，不能只看小数点。
2. **`l512` 那行是双变量**（max_len 512 + batch 16）：32×512 会越过 7GB 掉吞吐，
   只能降 batch，因此它不能与其它 max_len 格子严格并列。
3. **标题/正文是按首行启发式拆的**（98.3% 命中），不是官方字段；少数无标题样本的
   `title` 为空，会让 `title_only` 消融的 −4.69pp 略偏悲观。
4. **生成式与判别式不同库**：BERT 侧用 sklearn 的 P/R/F1，生成式侧自实现同口径函数；
   两者都按"全样本计入分母"计算，拒答算错，但没有做 seqeval 式的边界严格匹配
   （本任务是句子级分类，不涉及 span，影响可忽略）。
5. **API 结果是单次采样**（temperature=0，理论确定），但供应商侧模型版本可能静默更新，
   跨天复跑未必完全一致。

**如果继续做，优先级排序**：

1. 补 100k 上的 `max_len=384` + `lr=3e-5` 组合（当前消融都在 30k 的欠拟合区，结论未必可外推）；
2. 把 `class_weight=balanced` 与 `lr=3e-5` 同时开，验证两个 +1pp 是否可叠加还是互相抵消；
3. LoRA 数据量曲线（1k/5k/10k/20k）——回答"生成式路线需要多少数据才能追上 TF-IDF"。
