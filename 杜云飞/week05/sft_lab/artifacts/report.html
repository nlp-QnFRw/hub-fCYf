1三个关键设计

chat template

手写最小 ChatML，不用官方模板。

<|im_start|>user
什么是人工智能？<|im_end|>
<|im_start|>assistant

官方模板会往 assistant 段强塞 <think></think>， 而 Base 模型没有思考行为，学了只是噪声，还会让训练/推理格式不一致。

loss mask

提问段 labels = -100，只学回答段。

第一版把回答结尾写成 <|im_end|>，训练 2 个 epoch 后 stop_rate 仍然是 0——内容答对了，但停不下来，一直在复读。做了一次过拟合实验：只拿 32 条样本训 15 个 epoch，其余 token 的 loss 全降到 0，唯独 <|im_end|> 卡在 7.8 不动。查词嵌入才明白：它在 Base 词表里几乎是空行（行范数 0.35，普通汉字约 0.97，<|endoftext|> 是 1.10），而 Qwen3 的输出头与词嵌入共享权重（tied），这个 token 的 logit 几乎推不动。换成 Base 本来就会在句末预测的 <|endoftext|> 之后，一个 epoch 就学会了。
——这正是课件第 18 页那句话的另一面：SFT 改的是「怎么答」，改不了模型压根没见过的符号。

6局限与诚实声明

  • 训练数据本身含事实性噪声（例如个别算术题的数值不准），所以 char_f1 衡量的是「像不像参考答案」，不是「答得对不对」。
  • 0.6B 基座 + 3000 条短答案数据，能学会的是输出格式、长度分布、停止行为；换成长答案、多轮追问任务会明显吃力。
  • 只训了 2.0 个 epoch，属于「够用即止」，再训下去会开始背答案（课件第 20 页的灾难性遗忘）。
  • 评估用的是贪心解码（temperature=0），采样解码下措辞会更发散，但指标趋势一致。
