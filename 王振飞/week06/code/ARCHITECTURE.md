# ARCHITECTURE · 数据接入与分流（投研工作台第 1 块）

> 位置：八斗投研工作台「数据层 · 数据加工」的第一站。
> 上游是「数据来源」（公告年报 / 公开接口 / 语料），下游是「数据资产」和「第 9 周的工具层」。

---

## 一、项目定位

投研团队每天收到数百条公告与新闻，人工要先判断三件事：**是什么主题、跟我的持仓有没有关系、该进哪个队列**。
这就是「分流」，也是整条流水线的入口：分错主题 → 后面全错；分错相关性 → 噪音淹没投研；排错队列 → 该推的没推。

本项目把这一站拆成四层来做，并用同一批数据横向对比五种方法：

```
消息 → 规则快筛 → 模型分类（BERT / TF-IDF / LLM）→ 置信度闸门 → 队列路由
                     ↑ 全部在 500 条干净验证样本上评测
```

## 二、方案对比（统一 500 条干净验证样本，seed=42）

| 方法 | 层级 | 准确率 | Macro-F1 | 覆盖类别 | 训练成本 | 选型结论 |
|---|---|---|---|---|---|---|
| 规则 / 关键词 | L0 | 0.126 | 0.072 | 10/15 | 0 | 只能做快筛兜底（命中率仅 6.6%） |
| TF-IDF + LinearSVC | L1 | 0.512 | 0.472 | 15/15 | 20 秒（CPU） | **数据封闭场景（内网 / 无预训练权重 / 合规）首选**；通用场景只是基线 |
| **BERT 微调** | L2 | **0.556** | **0.544** | 15/15 | ~14 分钟（单卡 3 epoch） | **本任务最优**：封闭标签 + 短文本 |
| Qwen3-0.6B zero-shot | L3 | 0.168 | 0.105 | 8/15 | 0 | 冷启动可用，但**预测塌缩**，不可直接上线 |
| Qwen3-0.6B + LoRA SFT | L4 | 0.530 | 0.484 | 14/15 | ~44 分钟（5000×2，4060） | 能修好塌缩，仍落后判别式 6 个点 |
| Qwen3-0.6B 全量微调 | L4 | 0.536 | 0.492 | 14/15 | ~68 分钟（3000×2，峰值 5.58 GB） | 比 LoRA 多 0.8 个点，成本高一个量级 |
| API zero-shot（deepseek-v4-flash） | L3 | 0.514 | 0.471 | 15/15 | 0（按 token 计费） | 冷启动可用，追平 TF-IDF，仍低于 BERT |

补充口径（同一份数据，不同切分）：

| 切分 | TF-IDF Macro-F1 | BERT Macro-F1 |
|---|---|---|
| 全量 val（10,000，含 11% 重复） | 0.541 | 0.551（保存的 ckpt）/ 0.558（5 epoch 最佳） |
| 去重后（8,901） | 0.509 | 0.534 |

> **为什么保留两套口径**：全量 val 是「项目历史数字」，去重后才是「公平数字」。
> 两者都写出来，是为了让学生看到「评测集没洗干净，指标能虚高 3 个点」。

## 三、数据与标签口径

- **数据**：CLUE TNEWS，53,360 训练 / 10,000 验证，15 类中文新闻标题。
- **为什么要重映射**：新闻的 15 个类别不是投研关心的主题。`common/labels.py` 把它们收拢成 4 组
  （金融 / 产业 / 宏观 / 噪音），相关性二分类由组派生（金融 + 产业 = 相关），**零人工标注**。
  这件事本身就是教学点：换领域做分类，改的往往是映射表，不是模型。
- **数据泄漏**：验证集有 **1,099/10,000（11%）** 与训练集句子完全相同（源数据本身有重复）。
  靠词面匹配的 TF-IDF 会被显著抬高：

  | | 重复样本上 | 干净样本上 |
  |---|---|---|
  | TF-IDF | 0.85 | 0.51 |
  | BERT | 0.673 | 0.534 |

  所以 `common/data.py` 提供 `clean_val()`，全项目统一在去重后的样本上评测。

## 四、各环节技术选型

### 1) 规则快筛（`rule/`、`service/classify_news.py` 的 `FAST_RULES`）
- **为什么留**：公告标题有强套路（"年度业绩预告""回购""减持"），一条正则就能覆盖，省掉模型调用。
- **上限**：15 个类别名当关键词匹配，命中率只有 6.6%，Macro-F1 0.072 —— 说明它只能做「快筛」，不能做「分流」。

### 2) TF-IDF + LinearSVC（`tfidf/`）
- **为什么用字 n-gram 而不是分词**：中文标题平均 20 字，字 1-2gram 已能抓住「股/盘/楼/球/手机」这类信号，还省掉分词依赖。
- **它的定位**：通用短文本上它不是「强基线」，只是**基线**（0.472 vs BERT 0.544，差 7 个点）。
- **它真正的主场是数据封闭**：不能引入预训练模型（内网 / 无权重 / 合规）、语料是自有黑话、只有几百到几千条样本、
  还要能秒级重训 —— 这些场景里 20 秒训完的线性模型往往就是最终方案。
- **先跑它的理由**：20 秒就能知道这个任务的天花板大概在哪，再决定要不要付 14 分钟去换 7 个点。

### 2.1) 数据量实验：训练集越小，「微调」越值钱

为了回答「BERT 那 7 个点值不值」，另做了一组训练集比例扫描（独立实验，脚本不在交付代码里）：
同一批 8,901 条去重验证样本、按标签分层抽样（seed=42）、BERT 固定 3 epoch。

| 训练集比例 | 训练条数 | TF-IDF Macro-F1 | BERT Macro-F1 | 差距 |
|---|---|---|---|---|
| 100% | 53,360 | 0.5087 | 0.5345 | **+0.026** |
| 60% | 32,018 | 0.4927 | 0.5274 | +0.035 |
| 30% | 16,006 | 0.4864 | 0.5235 | +0.037 |
| 15% | 8,005 | 0.4593 | 0.5157 | **+0.057** |

- **谁掉得多**：TF-IDF 掉 4.9 个点（0.509 → 0.459），BERT 只掉 1.9 个点（0.534 → 0.516）——
  TF-IDF 只能复用训练集里出现过的字面特征，BERT 还有预训练知识垫底。
- **工程含义**：数据 < 1 万条优先微调预训练模型；数据充足且要低延迟/可解释时，传统方法差 2~3 个点换 30 倍速度也划算。
- **局限**：只跑了一个 seed，中间两点差异在噪声内，能站住的是两个端点；BERT 固定 3 epoch，数据少时真实差距可能更大。

### 3) BERT 微调（`bert/`）
- **改哪两处**：池化方式（cls/mean/max）和损失函数（类别加权）。BERT 本体 12 层不动。
- **三个旋钮**（比换模型值钱）：分层学习率（BERT 2e-5 / 头 ×5）、Warmup 10%、类别加权（23× 不均衡）。
- **实测**：9 组消融里单点增益都只有 1–2 个点，说明瓶颈在数据不在模型。
- **四个「训练技巧」都在代码里**（`--label_smoothing` / `--focal_gamma` / `--fgm` / `--no_class_weight`）：
  类别加权 0.5344（默认）· LS 0.1 → 0.5272（−0.7）· Focal γ=2 → 0.5345（±0）· FGM ε=1.0 → 0.5346（+0.02，训练 ×1.5）。
  同一批 8,901 条去重验证集、同 seed、3 epoch。**结论：本任务上只有类别加权有意义**，其余三个值得写的价值在于
  「知道什么时候不该用」——它们针对的是 >100× 不均衡或明显过拟合，这个任务两个都不占。
- **FGM 实现要点**：只扰动 `word_embeddings`；`r = eps·g/‖g‖` 必须归一化（否则 eps 的含义随梯度尺度漂移）；
  AMP 下用缩放后的梯度方向不变；训练循环里两次 backward 后一起 step。训练时间约 ×1.5。
- **冒烟参数**：`--max_steps N --max_eval N --no_save`，用于快速验证代码通不通（不跑全程、不落 390 MB 权重）。

### 4) Qwen3-0.6B zero-shot（`llm_zero_shot/`）
- **为什么还是要跑**：它是「没有标注数据时能拿到什么」的对照答案，也是很多团队第一反应。
- **必须传 `enable_thinking=False`**：否则模型先输出 `<think>` 推理链，格式全乱。
- **实测塌缩**：只输出 8/15 类，「文化」一类占比过半，Macro-F1 0.105。

### 5) Qwen3-0.6B + LoRA SFT（`llm_lora/`）
- **三个关键点**：chat 模板（训练与推理必须一致）、Loss Masking（prompt 上 `-100`）、LoRA（r=8，0.38% 参数，adapter 9 MB）。
- **效果**：把 zero-shot 的 0.105 拉到 0.484，覆盖 14/15 类；但仍落后 BERT 6 个点。
- **适用于**：要私有化、要处理没见过的表述（开放输出）时；封闭标签 + 高 QPS 不是它的战场。

### 6) 全量微调（`llm_lora/train_lora.py --full_ft`）
- **和 LoRA 的关系**：全量更新 596M 参数，LoRA 只训 0.38%；实测 Macro-F1 0.492 vs 0.484，**只多 0.8 个点**，但峰值显存 5.58 vs 3 GB、训练 68 vs 44 分钟、产物 1.2 GB vs 9 MB。
- **8G 卡上必须开梯度检查点**（`--gradient_checkpointing`），否则 OOM；全量微调用 bf16 + 小 lr（2e-5），LoRA 用 fp16 + 2e-4。
- **什么时候才值得**：数据 ≥ 10 万条、任务与预训练分布差异大、要把能力合并进模型做固定部署。

### 7) API 零样本（`llm_api_zero_shot/`）
- **和本地零样本的区别**：同一套 prompt，从 0.6B 本地模型换成 `deepseek-v4-flash`，Macro-F1 从 0.105 涨到 0.471，类别覆盖从 8/15 到 15/15。
- **代码写法**：标准 OpenAI 兼容调用（`OpenAI(base_url=..., api_key=...)` + `chat.completions.create`），换服务商只改环境变量。
- **两个真实坑**：① 推理模型不关思考会被 `max_tokens` 截断（500 条里 85 条空回复，指标虚高到 0.577）；关掉 thinking 后失败降到 2 条、延迟 2.4 s→1.0 s/条。② 解析失败必须计入准确率分母，否则生成式方法会「靠丢样本」虚高。

### 7.5) CLI 分流服务（`service/classify_cli.py`）
- **接口契约**：一条标题 → `{title, topic, sub_topic, relevant, conf, queue, model, version}`，与课件 P43 一致。
  下游只需要 conf + queue 就能做路由（低置信转人工 / 不相关直接丢），不需要理解模型内部。
- **后端选择**：`auto` → 有 `outputs/bert_ckpt.pt` 就用 BERT，否则退回 TF-IDF（SGD + log loss），再不行用规则兜底。
  **降级显式**：结果里的 `model` 字段写清楚走的是哪条路径，启动日志也会打印一行。
- **为什么不是 LinearSVC**：服务要输出置信度，SVC 没有 `predict_proba`；SGD(log_loss) 实测 macro-F1 0.518，
  与 LinearSVC 的 0.510 相当，训练还快（48k 条 10 秒内）。
- **置信度校准**：在没参与训练的留出集上拟合温度 T（TF-IDF 用 train 的 10%，BERT 用干净验证集 200 条），
  把 `softmax(log p / T)` 当作 conf。不校准的话，阈值 0.8 只放出 2.6% 的样本进 research —— 接口等于废掉。
- **CLI 形态**：交互 REPL / `--text` / `--file` / 管道；`--json` 输出一行一条，方便被 Agent 当工具调用（第 9 周）。

### 8) 服务组合（`service/`）
- **四段串联**：规则快筛 → 模型分类 → 置信度闸门（0.8）→ 队列路由（research/review/drop）。
- **接口契约**：`{topic, sub_topic, relevant, conf, queue, model, version}`。返回 `conf` 是给下游做决策用的，只回 label 等于没接口。
- **降级显式**：BERT 权重缺失时退回规则法，`model` 字段标记为 `fallback`，服务不崩。

## 五、Bad Case 分析

| 现象 | 典型例子 | 原因 | 处理 |
|---|---|---|---|
| 财经 ↔ 证券互吃 | "卡位龙：新光药业完胜"（真：财经，预测：体育/文化） | 标签口径本身重叠，短标题无实体 | 改标签口径（合并两类的业务定义），而不是继续调模型 |
| 科技 ↔ 国际互吃 | "华为晚间发微博…5G 方案" 类 | 公司新闻既属科技也属国际 | 引入多标签或二级标签，单标签任务到此为止 |
| zero-shot 塌缩 | 大量标题判成「文化」 | 15 类太多、prompt 未给定义、模型太小 | 换 few-shot / SFT / 换判别式；**不要靠调 prompt 硬修** |
| LoRA SFT 仍有 1 类未覆盖 | 「证券」从未被预测 | 5000 条采样里该类占比低 | 平衡采样 / 提高类别权重 / 增加训练量 |

## 六、优化方向

1. **数据**：清洗重复样本（已在 `common/data.py` 做了）、补长尾类、用真实 query 回流做增量。
2. **模型**：换 bert-large / RoBERTa-wwm-ext（预期 +2~3 点）；或蒸馏小模型保留延迟优势。
3. **训练**：R-Drop、EMA、多种子集成；类别加权之外再试 Focal Loss。
4. **工程**：ONNX / 量化把单条延迟从 265 ms 压下去；批处理（batch 32 → 138 ms/条）；阈值做成可配置。

## 七、关键工程决策与踩坑

| 问题 | 根因 | 解法 |
|---|---|---|
| `transformers 5.x` 下 `BertModel` 返回 tuple | 默认 `return_dict` 行为变化 | 显式 `return_dict=True`，取 `last_hidden_state` |
| `torch.load` 加载 ckpt 报错 | torch 2.6 默认 `weights_only=True` | 本地可信文件加 `weights_only=False` |
| Qwen3 输出带 `<think>` 块 | 默认开启思考模式 | 训练与推理都传 `enable_thinking=False`，且模板必须一致 |
| Mean/Max 池化效果异常 | 没 mask 掉 `[PAD]`，补位向量污染统计量 | `attention_mask` 参与池化，Max 时把 PAD 压到 `-1e9` |
| 指标不可比 | 一个脚本用 weighted F1、一个用 binary F1 | `common/metrics.py` 统一算，显式写 `average=` |
| 验证集虚高 3 个点 | 11% 样本与训练集重复 | 统一走 `clean_val()`；文档同时给「全量 / 去重」两套数 |
| 类别写死导致 target_modules 训了等于没训 | 名字写错不报错 | `print_trainable_parameters()` 必须打印 |
| 服务在没训练过的机器上崩 | 直接 `torch.load` 不判存在 | `_try_load()` 捕获异常 → 降级规则法并显式标记 |
| API 返回空串、指标异常偏高 | 推理模型先吐思考 token，`max_tokens=64` 被截断 | `max_tokens` 给足 256，或传 `thinking: disabled` 关掉思考 |
