# BERT + Linear 验证集错误分析

## 范围和口径

- 模型：`outputs/bert_linear.pt`；GPU 推理。
- 数据：老师提供的 `data/processed/dev_extract.jsonl`，930 条句级单事件样本。
- 与 `eval/evaluate.py` 一致，论元按 `(事件类型, 角色, 文本)` 构造集合并精确匹配，集合内重复项会去重。结果是数据集及这一评测实现的结果，不能代表篇章级真实业务效果。
- 这次重新运行推理，逐条预测及错误见 `bert_linear_predictions.jsonl`；结构化统计与样例见 `bert_linear_error_analysis.json`。

## 一、总体结果

触发词 F1 89.86%，论元 P/R/F1 = 63.02% / 74.45% / 68.26%，完整事件 F1 26.19%。论元 TP=3066、FP=1799、FN=1052。论元召回高于精确率，当前按标注口径多报较多；但不意味着每个 FP 都是语义错误，也可能是等价表述或标注不完整。

## 二、按文本切分分组

| 分组 | 条数 | 论元 P | 论元 R | 论元 F1 | 预测事件数 |
|---|---:|---:|---:|---:|---:|
| 单片段 | 808 | 65.38% | 74.86% | 69.80% | 792 |
| 多片段 | 122 | 51.83% | 72.09% | 60.30% | 187 |

多片段是按当前 `segments()` 和训练 checkpoint 的 max_length 得出的分组，并非随机对照；文本长度、事件复杂度等也有差异，因此不能把全部差距归因于切分。122 条多片段样本中合计预测 187 个事件，比每条一个多 65 个，产生额外事件/论元的可能性值得重点核查。

例如恒大高新的一条样本，金标是一个回购事件，但两片段分别抽到回购触发词，输出了两个回购事件。当前整体论元指标会将同类型论元集合合并，完整事件指标却分别判断事件，因此一组论元可能看起来基本找对，而整事件仍不匹配。不能简单按事件类型合并，否则同类型的真实不同事件会被错误合并。

## 三、误报启发式分类

对每个未匹配的预测论元，依次用简单字符串规则归类，分类是对 FP 条目的统计，并非经过人工确认的错误根因：

| 分类 | FP 数 | 占 1799 个 FP |
|---|---:|---:|
| 同类型、同角色，预测文本与未匹配金标互相包含 | 709 | 39.4% |
| 同角色、同文本，但事件类型不同 | 90 | 5.0% |
| 同类型、同文本，但角色不同 | 54 | 3.0% |
| 其他 | 946 | 52.6% |

一个金标论元可能对应多个短片段误报，因此不能把 709 理解为 709 个独立的边界错误事件。存在嵌套、重复值和标注差异时，这些规则可能误判。

### 例 1：空格把一个 span 切碎

金标披露时间是 `9 月 8日`，预测输出 `9`、`月`、`8日` 三个片段。`bert/predict.py` 只有在相邻 token 的字符 offset 严格相接时才合并；空格不产生 token，因此空格会中断片段。这是解码实现的明确问题，但尚需在整套验证数据上验证修复幅度及副作用。

### 例 2：同一事实多种写法

回购公告中金标金额为 `450万港元`，模型同时输出 `450万港元` 和 `约450万港元`。按精确文本匹配，后者被计为额外论元；从业务语义上它可能是同一金额的重复表述。另有 `6亿元` 与 `60,000.00万元` 的例子。业务去重需要金额归一化和事件关联，但不能简单删去同一角色的所有其他值。

### 例 3：类型混淆会连带影响多个论元

一条标注为“解除质押”的文本，模型预测成“质押”。即使部分角色及原文片段相同，按评测口径只要事件类型不同，这些论元仍不能命中。要对照原文和标注规范判断模型错误还是标注歧义。

### 例 4：标注本身也要审计

某条金标将 `140.2万` 标为“占公司总股本比例”，模型将其标为“回购股份数量”。按照数据集金标这是模型误报，但从文本字面看模型的角色可能更合理。这只是待核实的个例，不能据此认定整份标注有误。

## 四、需要谨慎解读的指标

1. 训练集与 dev 有 10/930 条文本完全相同（按完整字符串统计），可能使整体指标略偏乐观；需要进一步按文档、近重复及标签核查。此数字不等同于检测集的 9.2% 重复率。
2. 验证集样本都带事件，不能评估真实业务中无事件文本上的误报率。
3. 训练只按验证损失选最佳轮；event F1 很严格，不等同于业务正确率。
4. 当前实现的多字符 token 只用起点标签；特殊符号、空格、英文数字及截断会影响 span 还原。
5. 启发式归因没有人工标注；老师评测使用事件匹配与 Counter 等方式，和本项目集合式评测不同，成绩不能直接横向排名。

## 五、建议的下一步（先验证，再改）

1. 保持当前 checkpoint、数据和指标不变；针对空格 span 写例子，验证允许相同 I 标签跨纯空白合并后是否能恢复金标，同时检查不相关片段是否被错误连接。以完整 dev 同口径对照，记录 P/R/F1 和变坏案例。
2. 补充事件检测评测：使用包含负样本的数据，统计无事件文本的误报率及检测召回；避免正样本集上的高分误导实际应用判断。
3. 对长文本分析跨片段角色归属，先定义实体和事件关联标准，再评估安全的去重/合并；不能用“同类型即同事件”。
4. 将同一事实的多个表述、标注不一致和角色混淆各抽样人工检查，量化哪一类最值得优化。
5. 再用同一数据训练和评测 BERT+CRF，比较 span 错误、误报、F1、显存与耗时；不预设 CRF 一定更好。

复现：在 `diyCode` 目录执行 `python -m eval.analyze_errors --device cuda`。脚本会覆盖同名分析 JSON 和预测 JSONL。
