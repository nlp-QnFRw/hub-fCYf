# Week 07 信息抽取学习路线：从任务分析到模型选型

这份文档的目标不是让你记住几个训练命令，而是让你拿到一个新的 NLP 信息抽取任务时，能够回答：**任务是什么、数据怎么准备、先做什么基线、模型为什么这样选、实验如何公平比较、结果为什么会变好或变差、最后怎样上线。**

## 一、先建立正确的任务观

老师的项目不是“让模型读懂一篇文章”，而是把文本转换成一组可验证的结构化事件：

```text
输入：某公司拟回购股份，金额不超过一亿元。
输出：
事件类型：股份回购
触发词：回购
论元：回购方=某公司；交易金额=一亿元
```

这类任务同时包含三件事：

1. **事件分类**：发生了哪一种事件？
2. **触发词识别**：文本中哪个词说明事件发生？
3. **论元抽取与角色分配**：谁、什么时间、多少钱、多少股份分别填入哪个角色？

所以不能只看“分类准确率”。老师项目同时看：

- `trigger F1`：触发词找得准不准。
- `argument F1`：角色和对应文本片段填得准不准。
- `event_exact F1`：一个事件的类型、触发词和全部论元是否完全正确。

**最需要记住的判断：事件抽取的真正难点通常是论元角色和边界，不是判断有没有关键词。**

## 二、拿到一个新任务，按这个顺序规划

### 第 1 步：先写清输入和输出契约

先不要急着选 BERT 或大模型，先回答：

| 问题 | 必须明确的内容 |
|---|---|
| 输入粒度 | 一句话、一个段落，还是整篇文档？ |
| 输出对象 | 实体、关系，还是事件？ |
| 是否允许多个结果 | 一句一个事件，还是一句多个事件？ |
| 是否需要原文位置 | 只要文本，还是要 `start/end`？ |
| 角色集合 | 每种事件允许哪些角色？ |
| 空结果 | 没有事件时输出什么？ |
| 线上约束 | 延迟、显存、成本、隐私、可解释性？ |

老师项目先把篇章级 DuEE-Fin 转成“**一句话 + 一个事件**”，原因是单层 BIO 序列很难表达一句话里的多个重叠事件。这是一个关键的任务建模决定。

### 第 2 步：审计数据，而不是直接训练

你至少要检查：

- 文本和标注 span 是否真的对应：`text[start:end] == 标注文本`。
- 训练集和验证集是否重复。
- 事件类型和角色是否长尾。
- 句子长度是否会超过模型输入上限。
- 负样本比例是否很高。
- 一个文档 ID 是否对应多条句子。

老师项目中有几个必须掌握的教训：

- `id` 是文档 ID，不一定唯一；评测要用 `id + sent_id` 对齐。
- 检测集负样本约 77.9%，只看 accuracy 会产生假象。
- dev 检测数据与训练文本存在重复，因此要同时看全量和 clean 评测。
- 原始论元位置需要校验，不能默认数据无误。

**数据审计的目的，是知道你的指标是否可信。**

### 第 3 步：先做“能解释的基线”

建议固定顺序：

1. **规则基线**：词典、触发词、日期/金额/比例正则。
2. **BiLSTM-CRF**：无预训练模型，理解序列标注本身。
3. **BERT + Linear**：加入预训练知识。
4. **BERT + CRF**：研究标签之间的依赖和非法 BIO。
5. **两段式 Pipeline**：检测 → 类型 → 类型条件论元。
6. **LLM zero/few-shot**：研究提示词和生成式输出。
7. **LoRA SFT**：有明确数据和显存预算时再做微调。
8. **系统组合**：模型、规则、校验和人工复核组合。

不要一开始就只训练最复杂的模型。没有规则基线和 Linear 对照，你无法解释 CRF 或大模型到底带来了什么。

## 三、每一种方法到底解决什么问题

### L0：规则

**适合：** 触发词固定、数值格式稳定、需要极低延迟的场景。

**优势：** 不需要训练，快，可解释。

**短板：** 能找到“回购”“减持”，却不一定知道句子中的哪个金额属于交易金额、哪个人是减持方。

老师的结果说明：规则的触发词能力可以不错，但论元 F1 明显较低。这不是规则毫无价值，而是它暴露了模型真正要解决的缺口。

### L1：BiLSTM-CRF

**你要掌握：**

- embedding 把字符变成向量。
- BiLSTM 同时看左上下文和右上下文。
- CRF 对整条标签序列建模。
- `B-角色 / I-角色 / O` 的边界含义。

**它的学习价值：** 它是理解“预训练为什么有用”的对照实验。老师代码中，BiLSTM 的触发词能力接近 BERT，但论元边界明显弱于 BERT，说明预训练知识对语义和边界更有帮助。

### L2：BERT + Linear

BERT 负责上下文表示，Linear 负责每个 token 的标签分类。它简单、快，是最重要的主线基线。

你必须掌握：

- BERT 的输入、输出和 attention mask。
- tokenizer 的 token 与原文字符如何对齐。
- 为什么特殊 token、padding 和非首子词通常设为 `-100` 并忽略 loss。
- 为什么联合标签会有 `149` 个：`O + 触发词的 B/I + 角色的 B/I`。

### L2：BERT + CRF

Linear 对每个 token 独立判断，可能出现 `O → I-金额` 这种非法 BIO 序列。CRF 学习标签转移，使整条序列更合理。

你必须理解三个算法概念：

1. **路径分数**：起始分数 + 发射分数 + 转移分数 + 结束分数。
2. **前向算法**：用动态规划计算所有路径的 `logZ`。
3. **维特比算法**：用动态规划找最高分路径，并保存回溯指针。

老师项目最值得学习的结论：

- 软 CRF 能减少非法转移，但不等于严格禁止非法路径。
- 加解码期硬约束，可以在不重新训练的情况下明显提升论元和事件指标。
- 约束加载后要重新检查，不能只相信配置已经生效。

### L2：联合模型 vs 两段式 Pipeline

**联合模型：** 一个模型一次预测事件类型、触发词和论元。

**两段式：**

```text
是否有事件 → 事件类型 → 该类型的论元抽取
```

两段式的理论优点是每个专家的标签更少；实际代价是：

- 类型预测错了，后面的论元专家全部受影响。
- 数据被拆到多个专家，训练步数可能严重不足。
- 模型数量、加载时间和维护成本增加。

老师代码的实验告诉你：**不能只看标签数量少不少，要算每个模型真正拿到多少训练信号。** 小数据、单卡环境下，联合 BERT 往往更稳。

### L3/L4：LLM zero/few-shot 和 LoRA

**zero-shot：** 只给任务说明和 schema，不给示例。

**few-shot：** 在提示中加入少量输入输出示例。

**LoRA SFT：** 用任务数据训练少量 adapter 参数，让小模型学习固定输出格式和领域口径。

必须掌握的原则：

- 让模型输出原文片段，不要让模型自己生成 start/end；程序再用原文匹配回填位置。
- JSON 合法不等于字段合法，仍需检查事件类型、角色和片段是否在原文中。
- 评测时解析失败样本不能删除，否则指标会虚高。
- LoRA 的 loss masking 应只在目标 JSON 上计算，不能让 prompt 占据主要 loss。

老师项目体现出一个很实用的取舍：生成式模型的召回和格式适应能力强，判别式模型的边界精确性通常更稳定。

## 四、如何设计公平的对比实验

### 先固定不变的东西

所有方法都尽量固定：

- 同一份训练集和 dev 集。
- 同一个事件 schema。
- 同一套输入粒度。
- 同一个预测 JSON 格式。
- 同一个评测函数。
- 同一个样本子集和随机种子。

否则你比较的可能不是模型，而是数据和评测口径。

### 推荐的实验矩阵

| 实验 | 目的 | 主要观察 |
|---|---|---|
| 规则 | 建立下限和错误类型 | 规则擅长什么，缺什么 |
| BiLSTM-CRF vs BERT | 量化预训练收益 | 触发词和论元各提升多少 |
| BERT Linear vs CRF | 研究序列约束 | 非法 BIO、论元边界、延迟 |
| CRF 软约束 vs 硬约束 | 研究解码改进 | 不重训能提升多少 |
| max_len 128 vs 256 | 研究截断代价 | 被截断比例和 F1 变化 |
| BERT 4 层 vs 12 层 | 研究模型容量 | 速度、显存和论元能力 |
| 联合 vs 两段式 | 研究架构取舍 | 类型错误还是论元训练不足 |
| zero vs few-shot | 研究提示示例价值 | JSON 合法率、论元和成本 |
| BERT vs LLM | 研究判别式/生成式 | 精度、边界、延迟、费用 |

### 每次实验都要记录

```text
数据版本
训练样本数 / dev 样本数
模型结构和层数
max_length / batch / epoch / 学习率
训练时长和峰值显存
推理延迟
trigger / argument / event_exact F1
错误样例
```

不要只保存一个最终 F1。真正有价值的是知道“哪个环节造成了损失”。

## 五、如何判断谁是最优

“最优”不是永远等于最高 F1，而是由业务目标决定：

| 业务目标 | 优先选择 |
|---|---|
| 离线批处理，优先完整结构 | BERT + CRF 或硬约束 CRF |
| 在线高吞吐，延迟敏感 | BERT + Linear，必要时规则兜底 |
| 类型和角色经常变化 | LLM few-shot 或 LoRA |
| 不能上传文本，有本地模型要求 | BERT / 本地 LLM |
| 需要强可解释性 | 规则 + BERT + 校验 |
| 金额、日期、比例字段很多 | 模型抽结构 + 正则补数值 |
| 低置信结果必须可追踪 | 任意模型 + schema/span 校验 + needs_review |

在老师项目的指标中，BERT+CRF 比 Linear 的收益主要体现在论元和完整事件；但它训练、推理更慢。大模型路线可能有更好的召回，但会带来 API 成本、格式风险和数据外发问题。

因此真正的工程答案通常是：

```text
规则快速筛选/补充
    ↓
BERT 或 LLM 抽取结构
    ↓
schema 校验 + 原文 span 校验
    ↓
低置信或缺核心角色 → 人工复核
```

## 六、你必须掌握的知识清单

### A. 任务与数据

- 事件、触发词、论元、角色、span、schema。
- 句级单事件和篇章级多事件的区别。
- 数据泄漏、重复样本、长尾类别、负样本比例。
- `id + sent_id` 对齐和字符 offset 校验。

### B. 序列标注

- BIO / BIOES 标签。
- 字符级标签和 token 级标签的转换。
- tokenizer offset / word_ids 对齐。
- padding、mask、`ignore_index=-100`。
- 截断如何影响召回和边界。

### C. 模型原理

- embedding、BiLSTM、Transformer、BERT 预训练和微调。
- Linear 独立分类的局限。
- CRF 的路径分数、前向算法、维特比解码。
- 软约束、硬约束和非法序列。
- 联合模型、流水线模型、误差累积。

### D. 评测与实验

- precision、recall、F1。
- trigger / argument / event_exact 三级指标。
- macro F1 和长尾类别。
- oracle 上界和误差归因。
- 固定数据、固定样本、固定评测函数。
- 指标、延迟、显存、成本的共同权衡。

### E. 生成式抽取与上线

- zero-shot、few-shot、SFT、LoRA、loss masking。
- JSON 合法率、schema 合法率、原文幻觉率。
- 不让模型生成 offset，程序回填位置。
- 规则兜底、校验、needs_review、人工闭环。
- 长文切分和全文坐标恢复。

## 七、建议的六周学习路径

### 第 1 周：读懂数据和任务

只做数据审计：读 `event_schema.json`、抽样看 20 条数据、手工写出事件结构、验证 span。目标是不用看代码也能解释一条样本。

### 第 2 周：手写规则和评测

实现触发词词典、日期/金额正则和三级 F1。重点不是规则效果，而是学会把“预测”和“金标”变成可比较的集合。

### 第 3 周：理解 BIO 和 BiLSTM-CRF

手动把一句话标成 BIO；看 embedding、BiLSTM、CRF 的输入输出；用小数据跑通训练，并观察非法序列。

### 第 4 周：掌握 BERT 序列标注

重点读 tokenizer 对齐、训练循环、checkpoint、内部验证集和 max_length 消融。先跑 Linear，再跑 CRF，做公平对照。

### 第 5 周：理解架构和 LLM 对比

分析联合和两段式的误差；运行 zero/few-shot；统计 JSON 合法率、幻觉片段、延迟和成本。不要只看 F1。

### 第 6 周：系统化上线

读 service：切分、抽取、校验、规则兜底、needs_review、篇章合并。最后能画出自己的系统架构并解释每个模块为什么存在。

## 八、每次遇到新任务的决策卡

```text
1. 输出是实体、关系还是事件？
2. 一条输入可能有几个结果？是否有重叠？
3. 有没有可靠的 schema 和标注 span？
4. 先做规则基线，找出规则解决不了的错误。
5. 数据量够不够训练 BERT？输入长度是否超过上限？
6. 目标是边界精度、召回、延迟、成本还是可解释性？
7. 用 Linear 建主线，用 CRF 研究序列约束。
8. 只有在类型或角色拆分有充分数据时才做两段式。
9. 类型变化快、标注少时考虑 LLM few-shot。
10. 所有输出都经过 schema 和原文 span 校验。
11. 用统一评测和固定子集比较，不凭感觉选模型。
12. 最终选择“业务代价最小”的方案，而不是单一指标最高的方案。
```

## 九、你应该能讲清楚的最终答案

当别人问“为什么这样选模型”，你应当能够这样回答：

> 我先把任务定义为事件类型、触发词和角色论元的结构化抽取，确认输入粒度、schema、span 和多事件情况；然后用规则建立可解释基线，用 BiLSTM-CRF 对比无预训练能力，再用 BERT+Linear 建主线，用 CRF 验证序列约束是否改善边界。所有方法使用同一数据和评测口径，同时报告 trigger、argument 和 event_exact，避免只看分类指标。若两段式的类型专家有足够数据且论元是主要瓶颈，再做流水线；若类型经常变化或标注很少，再引入 LLM zero/few-shot。上线时采用模型抽结构、规则补规律字段、schema/span 校验和低置信人工复核的组合，并根据精度、延迟、成本和隐私选择最终方案。
