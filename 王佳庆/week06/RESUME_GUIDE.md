## 三、完整项目介绍（可直接粘贴到简历项目栏）

> **投研工作台 · 数据接入与分流模块（个人项目 / 2026.11）**
> **背景**：投研团队每天收到数百条公告与新闻，需人工判断主题、相关性，再分发到不同队列。
> **主要工作**：
> 1) 接入巨潮公告、AkShare 行情财务与公开语料，统一清洗为 title/summary/source/time 四字段；
> 2) 把 TNEWS 15 类重映射为 4 组投研主题 + 相关性二分类，标签由规则派生，零人工标注；
> 3) 七条路线横向对比：规则、TF-IDF+SVM、BERT 微调、本地 Qwen3（zero-shot / LoRA / 全量微调）、外部 API 零样本，同一验证集口径；
> 4) 训练侧用分层学习率 + warmup + 类别加权 + FGM + Label Smoothing，9 组消融定位出瓶颈在数据而非模型；
> 5) 落地为 `classify_news()` 服务：返回主题/相关性/置信度/队列，低置信转 LLM 兜底，接入早报面板。
> **结果**：
> · BERT 微调 Macro-F1 0.544（同批 500 条），较 TF-IDF 基线 +7.2pt；batch32 推理 138 ms/条（CPU）；
> · 发现验证集与训练集 11% 重复，去重后重评 BERT 0.534 / TF-IDF 0.509（全量干净集），结论不变；
> · Qwen3-0.6B zero-shot 仅 0.105（预测塌缩），LoRA SFT 提升到 0.484，仍落后判别式 6pt。
> **亮点**：定位并修复评测集数据泄漏；给出封闭标签任务下「判别式 vs 生成式」的选型判据与置信度阈值方案。
> **技术栈**：PyTorch / Transformers / PEFT(LoRA) / scikit-learn / 巨潮 API / AkShare

## 四、按岗位裁剪

### 算法工程师方向（强调对比实验与方法论）
- 一句话：在 5.3 万条中文短文本上完成**判别式 vs 生成式**的系统性对比，给出选型判据与量化结论。
- 重点写：四路方案同口径评测、9 组消融、数据泄漏发现、类别加权处理长尾。
- 面试展开点：数据封闭场景下为什么传统方法还够用？为什么 zero-shot 会塌缩？LoRA 的 r 怎么选？

### 后端 / 应用工程方向（强调接口与稳定性）
- 一句话：把多源资讯接入并封装成**带置信度的分流服务**，支撑下行队列路由与人工复核。
- 重点写：接口契约（topic/relevant/conf/queue）、阈值兜底、规则快筛省调用、权重缺失时显式降级。
- 面试展开点：为什么接口要返回 conf？阈值怎么定？服务怎么保证不挂？

### 应届 / 转行（强调动手完整度）
- 一句话：独立完成从数据清洗、四路建模、评测口径到服务封装的全链路。
- 重点写：自己发现并修复了评测集泄漏（这一条最能证明「不是照着教程抄」）。

### 1–3 年（强调工程判断）
- 一句话：在成本约束下做选型——用 0.6B 模型做零样本验证可行性，再决定是否投入标注与训练。

### 3 年以上（强调取舍与风险）
- 一句话：建立「数据质量 → 方案选型 → 服务契约」的评估框架，并把结论沉淀为可复用的评测脚本。

## 六、面试大概率会问（附答题要点）

1. **为什么最后没用大模型？**
   封闭标签 + 短文本：判别式更省更准（0.544 vs 0.484），延迟低两个量级；大模型留作低置信兜底。

2. **类别不均衡怎么处理？**
   23× 不均衡 → `compute_class_weight` + 加权 CrossEntropy；看 per-class recall 而不是总分（尾部类从「归零」到「有分」）。

3. **置信度阈值怎么定？**
   在真实分布上扫阈值画 PR 曲线，取误推率可接受的点（默认 0.8）；同时看 ECE，模型过度自信时先做校准。

4. **数据泄漏是怎么发现的？**
   训练/验证逐条做集合交集，发现 11% 完全重复；去重后重评，结论不变但数字回落——所以对外只报去重后的数。

5. **BERT 比 TF-IDF 只高 7 个点，值吗？**
   值不值得看场景：高 QPS + 延迟敏感 → TF-IDF 就够；要处理长尾/复杂表述 → BERT。这里选 BERT 是因为它还要作为工具被 Agent 调用。

6. **LoRA 的 r 怎么选？**
   4–16 起步，任务越复杂可以往上；本任务 r=8 已能拿到全量微调大部分收益（0.38% 参数）。调大 r 收益很快饱和，显存压力却上来。

7. **Loss Masking 是干什么的？**
   SFT 时 prompt 部分 labels 设 -100，只在答案 token 上算 loss；否则模型学的是复述模板，不是答标签。

8. **zero-shot 为什么塌缩？**
   15 个类别、prompt 没有类别定义、0.6B 模型容量小；模型倾向输出高频/泛化词（「文化」「科技」），导致类别覆盖只有 8/15。

9. **如果让你把它做到 0.6 F1 以上，怎么做？**
   先修数据（长尾补样本、口径合并），再换更大模型/蒸馏，最后才是调参和集成——顺序不能反，因为瓶颈在数据。

10. **同样是零样本，本地 0.6B 和 API 大模型差在哪？**
    0.105 vs 0.471：本地模型容量小，15 类里只输出 8 类（塌缩）；API 大模型能覆盖 15 类、追平 TF-IDF。但按 token 计费、数据出网，量大或涉密时仍要转本地。

11. **LoRA 和全量微调怎么选？**
    实测 0.484 vs 0.492，多 0.8 个点；但全量要 5.58 GB 显存、68 分钟、1.2 GB 权重，LoRA 只要 3 GB、44 分钟、9 MB。数据量不大时先上 LoRA。

12. **这个服务怎么保证不挂？**
    规则快筛 + 模型 + 阈值三段都有兜底；权重缺失时降级规则法并打标记；接口字段向后兼容，加 version。
